# ⚙️ Core API Reference

This technical reference manual documents the internal functions and helper modules that power Exon CLI's compilation engine under the hood. Use this guide if you are developing custom plugins, modifying scaffolding behaviors, or integrating Exon into your own automation pipelines.

---

## 🗄️ Database Resolvers

### `resolveDbTemplate`

Determines the relative path to the database template folder based on the user's primary programming language and target database ORM/ODM.

<ParamField path="options" type="Object" required>
  <Expandable title="properties">
    <ParamField path="language" type="string" required>
      Programming language chosen. Expected values: `TypeScript` or `JavaScript`.
    </ParamField>
    <ParamField path="database" type="string" required>
      Database ORM selection. Expected values: `Mongoose`, `Prisma`, `Drizzle`, or `None`.
    </ParamField>
  </Expandable>
</ParamField>

<ResponseField name="return value" type="string | null">
  Returns a relative template folder path (e.g., `mongoose/ts` or `prisma/js`). Returns `null` if database is set to `None`.
</ResponseField>

```typescript Example usage
const path = resolveDbTemplate({ language: 'TypeScript', database: 'Prisma' });
console.log(path); // Output: "prisma/ts"
```

## 🔄 Dependency & Environment Merging

### `mergeDeps`

Reads dependency declarations from the plugin/database template folder's `deps.json` and safely merges them into the root `package.json` of the scaffolded application.

<ParamField path="targetDir" type="string" required>
  The absolute file system path to the target generated project root.
</ParamField>
<ParamField path="depsPath" type="string" required>
  The absolute path to the `deps.json` file inside the target template.
</ParamField>

*   **Mechanism**: Automatically detects and aggregates `dependencies`, `devDependencies`, and `scripts` blocks, overwriting existing package version entries only if the template specifies a newer version.

---

### `appendEnv`

Appends environment configurations to the generated project's `.env` configuration file without erasing existing variables.

<ParamField path="targetDir" type="string" required>
  The absolute file system path to the target generated project root.
</ParamField>
<ParamField path="envPath" type="string" required>
  The absolute path to the `env.append` file containing the environment variables to append.
</ParamField>

---

### `mergeDbConfigToRoot`

Copies database configuration templates directly into the project's root or `src/db/` directory, while automatically filtering out builder files (`env.append`, `deps.json`, internal scripts, and schema files that are compiled separately).

<ParamField path="targetDir" type="string" required>
  The absolute file system path to the target generated project root.
</ParamField>
<ParamField path="templateDir" type="string" required>
  The absolute path to the selected DB template folder source.
</ParamField>

## 🐳 Containerization Builders

### `addDocker`

Orchestrates the creation and setup of Docker files. Checks the command-line options and, if the `--docker` flag is absent, displays interactive prompts to confirm setup with the developer.

<ParamField path="options" type="Object" required>
  CLI parameters parsed from `commander`.
</ParamField>
<ParamField path="language" type="string" required>
  Language choice: `TypeScript` | `JavaScript`.
</ParamField>
<ParamField path="targetDir" type="string" required>
  The absolute file system path to the target generated project root.
</ParamField>

---

### `createDockerFile`

Compiles and writes an optimized, multi-stage `Dockerfile` and a `.dockerignore` file matching the project's framework features.

<ParamField path="language" type="string" required>
  Language choice: `TypeScript` | `JavaScript`.
</ParamField>
<ParamField path="targetDir" type="string" required>
  The absolute file system path to the target generated project root.
</ParamField>

*   **Output Details**: Scaffolds a lightweight, multi-stage Docker build separating intermediate compilation steps from runtime container execution, ensuring ultra-small target production image sizes.
