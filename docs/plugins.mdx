# 🔌 Dynamic Plugin System

A major limitation of traditional Express scaffolders (such as `express-generator`) is their monolithic nature. Once the project is generated, altering the database layer, documentation, or logging system requires extensive manual refactoring.

**Exon CLI** solves this by implementing a **decoupled plugin architecture**. Each feature—from the database ORM to realtime WebSockets—is a dynamic plugin. You can add or remove these plugins at any point in your project lifecycle with zero configuration conflicts.

---

## 📦 Available Plugins & Details

Exon CLI comes pre-loaded with several high-performance plugins tailored for modern node.js development:

### 🐳 Docker Support (`docker`)
Generates optimized Docker setups for local development and high-performance containerized hosting.
*   **Files Added**:
    *   `Dockerfile`: Multi-stage build target separating build stages from production runs.
    *   `.dockerignore`: Excludes heavyweight files like `node_modules` or `.env` from contexts.
    *   `docker-compose.yml`: Local orchestrator binding database services and your API.

### 📝 Swagger OpenAPI Documentation (`swagger`)
Installs and pre-configures Swagger UI, mapping custom routes and payload schemes directly in a web panel.
*   **Endpoint**: `/docs`
*   **Files Added**: `src/routes/swagger.routes.ts` or `.js`, `src/config/swagger.ts` or `.js`

### 🪵 Winston & Morgan Logger (`logger`)
Adds an enterprise-grade, configurable logging framework replacing unreliable `console.log` statements.
*   **Transports**: Console log outputs and automated daily rotating file logs.
*   **Files Added**: `src/utils/logger.ts` or `.js`, integrations in `src/app.ts`

### ⚡ Realtime WebSockets (`socket`)
Pre-configures a robust **Socket.IO** instance directly attached to your core Express server.
*   **Files Added**: `src/socket/index.ts` or `.js`
*   **Capabilities**: Ready-to-go room management, socket connections, and namespace event mapping.

### 🗄️ Database ORMs & ODMs
Exon CLI offers three first-class database plugin options:

| ORM/ODM | CLI Name | Target Database | Description |
| :--- | :---: | :---: | :--- |
| **Prisma** | `prisma` | PostgreSQL, MySQL, SQLite | Advanced type-safe query building and automated migration schemas. |
| **Mongoose** | `mongoose` | MongoDB | Standard object data modeling for document-based databases. |
| **Drizzle** | `drizzle` | PostgreSQL, MySQL, SQLite | Lightweight, ultra-fast SQL query execution with type safety. |

## 📋 Managing Plugins

### Installing a Feature
To insert a new feature plugin into an existing Exon project, run the `add` command from your project's root directory:

```bash
npx exon-cli add <plugin-name>
```

For example, to configure auto-generated Swagger UI docs:

```bash
npx exon-cli add swagger
```

---

### Uninstalling a Feature
If your project requirements change, you can remove a plugin cleanly. Exon CLI automatically removes the associated files, strips import statements, and resets server configurations:

```bash
npx exon-cli remove swagger
```

---

## 🛠️ State Management (`exon.config.json`)

Exon keeps track of all active features in a lightweight JSON configuration file stored in the root folder of your project. This prevents double installations and manages uninstall cleanups safely.

```json
{
  "language": "TypeScript",
  "database": "PRISMA",
  "plugins": [
    "docker",
    "prisma",
    "logger",
    "swagger",
    "socket"
  ]
}
```
