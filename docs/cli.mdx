# 💻 Command-Line Interface Reference

Exon CLI is highly flexible, supporting both automated script workflows (via options/flags) and comfortable manual workflows (via interactive terminal prompt questions).

---

## ⚡ Project Creation: `create`

Scaffold a brand-new Express.js API instantly.

```bash
# General Syntax
exon-cli create <project-name> [options]
```

### Options & Flags

Customize the generated boilerplate template by appending these flags:

<ParamField path="--ts, -t" type="flag">
  Bootstrap a **TypeScript** project environment. This is the default setting. Generates structured `.ts` entrypoints, custom type definitions, and a rigid, high-performance `tsconfig.json`.
</ParamField>

<ParamField path="--js, -j" type="flag">
  Bootstrap a **JavaScript** project environment using modern **ES Module** (`import`/`export`) syntax instead of traditional CommonJS (`require`).
</ParamField>

<ParamField path="--prisma, -p" type="flag">
  Pre-integrate **Prisma ORM** inside the `src/db` directory. Scaffolds initial connection clients, migration setups, and schema definitions.
</ParamField>

<ParamField path="--mongoose, -m" type="flag">
  Pre-integrate **Mongoose ODM** inside the `src/db` directory. Generates ready-to-use MongoDB clients, connection configurations, and schema templates.
</ParamField>

<ParamField path="--drizzle, -d" type="flag">
  Pre-integrate **Drizzle ORM** inside the `src/db` directory. Pre-loads database adapters, migration schemas, and configuration parameters.
</ParamField>

<ParamField path="--docker, -D" type="flag">
  Add containerization support instantly. Generates a production-ready multi-stage `Dockerfile`, a `.dockerignore` file, and a complete `docker-compose.yml` local orchestration setup.
</ParamField>

<ParamField path="--logger, -L" type="flag">
  Enable structured enterprise logging. Installs and configures **Winston** (console + rotating file logging) and **Morgan** HTTP request middleware.
</ParamField>

<ParamField path="--swagger, -S" type="flag">
  Auto-generate interactive API documentation. Configures **Swagger UI** endpoints available at `/docs` with sample route schemas.
</ParamField>

<ParamField path="--socket" type="flag">
  Enable real-time **Socket.IO** server support. Scaffolds connection handlers, listener events, and binds them to the primary HTTP server.
</ParamField>

### Setup Examples

<CodeGroup>
```bash Fully Loaded (TypeScript)
# Generate a strict TS api with Prisma database support and Docker containerization:
npx exon-cli create ecommerce-api --ts --prisma --docker --swagger
```

```bash Lightweight (JavaScript)
# Generate a lightweight JavaScript API with Mongoose database and Swagger documentation:
npx exon-cli create microservice-api --js --mongoose --swagger
```
</CodeGroup>

## 🔌 Feature Plugin Management: `add` & `remove`

Exon's design allows you to add or remove core tech stacks dynamically as your repository grows. These commands must be executed within your Exon project's root folder.

### Adding a Plugin

```bash
# General Syntax
exon-cli add <plugin-name>
```

#### Available Plugins:
*   `prisma`: Install and scaffold the Prisma ORM.
*   `mongoose`: Install and scaffold the Mongoose MongoDB ODM.
*   `drizzle`: Install and scaffold the Drizzle ORM.
*   `docker`: Scaffold Docker files and multi-stage configurations.
*   `logger`: Add Winston & Morgan logger layers.
*   `swagger`: Add Swagger documentation configuration.
*   `socket`: Add Socket.IO realtime server modules.

```bash Example
npx exon-cli add docker
```

---

### Removing a Plugin

If you no longer require a specific tool or ORM in your setup, you can remove it cleanly. Exon CLI will automatically strip files and configuration imports.

```bash
# General Syntax
exon-cli remove <plugin-name>
```

```bash Example
npx exon-cli remove mongoose
```
